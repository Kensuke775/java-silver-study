## 問題2-1

**要点**

- `i++`(後置)は「現在の値を式の結果として使ってから、変数を1増やす」、`++i`(前置)は「先に1増やしてから、その結果を式の値として使う」
- 1つの式の中で同じ変数に複数回`++`/`--`が現れても、Javaでは評価順序が左から右へと明確に定義されている(C言語のような未定義動作にはならない)

以下のコードを実行すると何が出力されるか。

```java
public class Main {
    public static void main(String[] args) {
        int i = 1;
        int result = i++ + ++i;
        System.out.println("i:" + i + ", result:" + result);
    }
}
```

A. `i:3, result:4`
B. `i:3, result:5`
C. `i:2, result:3`
D. コンパイルエラーになる

<br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br>

**実施記録**

回答：A
正解：A
迷ったポイント：なし

## 問題2-2

**要点**

- `i = i++;`は「iの現在値を式の結果として保存 → iを1増やす(内部的な一時的変化) → その保存しておいた古い値を改めてiに代入し直す」という流れになる
- 右辺の`i++`によるインクリメントの効果は、その後の代入によって上書きされる

```java
public class Main {
    public static void main(String[] args) {
        int i = 5;
        i = i++;
        System.out.println(i);
    }
}
```

A. `6`
B. `5`
C. コンパイルエラーになる
D. 実行時に例外がスローされる

<br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br>

**実施記録**

回答：A
正解：B
迷ったポイント：「後置`++`は使われた後にインクリメントされる」という理解自体は正しかったが、その次に代入`i = (i++の結果)`が起きて古い値(5)がiに上書きされることまで見落とし、内部的に一瞬6になった変化が消える点に気づけなかった

## 問題2-3

**要点**

- `byte`型は-128〜127の範囲で表現される
- `b++`は内部的に`b = (byte)(b + 1)`と同じ扱いになり、キャストが暗黙的に行われるため、範囲外になってもコンパイルエラーにはならない
- 範囲を超えた場合は例外にはならず、値がラップアラウンド(一周)する

```java
public class Main {
    public static void main(String[] args) {
        byte b = 127;
        b++;
        System.out.println(b);
    }
}
```

A. `128`
B. `-128`
C. コンパイルエラーになる
D. 実行時に`ArithmeticException`がスローされる

<br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br>

**実施記録**

回答：A
正解：B
迷ったポイント：不安。「`b++`が暗黙的にキャストされる」という理解自体は正しかった(ただし最初shortと言い間違えた点は口頭で訂正済み、byteとshortは別の型)。ただしそのキャストが「128をそのまま収める」のではなく、byteの表現範囲(-128〜127)を超えた分がオーバーフローして下限の-128に折り返る、という点を見落としていた。追加検証: `(byte)(b + 1)`のように暗黙キャストを手動で書くと、同じ`127 + 1`でも`int`のまま(キャストなし)なら`128`になるが、`byte`にキャストした瞬間だけラップアラウンドして`-128`になる(`byte b=127; byte b_2=(byte)(b+1); System.out.println(127+1); System.out.println(b_2);` → `128` / `-128`)

## 問題6-1

**要点**

- `short`と`int`のような異なる数値プリミティブ型同士を`==`で比較すると、より大きい方の型に自動的に昇格(数値昇格)されてから値が比較される
- `float`と`double`も同様に、数値として昇格されてから比較される
- `String`同士の`==`は「文字列の中身」ではなく「参照(同じオブジェクトかどうか)」を比較する。文字列リテラルはString定数プールで共有されるが、`new String(...)`で明示的に生成したオブジェクトは別物として扱われる

```java
public class Main {
    public static void main(String[] args) {
        short s = 10; int i = 10;
        float f = 10.0F; double d = 10.0;
        char a = 'a';
        String s1 = "Duke";
        String s2 = new String("Duke");
        System.out.println("s == i   : " + (s == i));
        System.out.println("f == d   : " + (f == d));
        System.out.println("a != 'A' : " + (a != 'A'));
        System.out.println("s1 == s2 : " + (s1 == s2));
    }
}
```

A. `s==i:true` / `f==d:false` / `a!='A':true` / `s1==s2:true`
B. `s==i:true` / `f==d:true` / `a!='A':true` / `s1==s2:false`
C. `s==i:true` / `f==d:true` / `a!='A':false` / `s1==s2:true`
D. コンパイルエラーになる。異なるプリミティブ型同士を`==`で直接比較することはできないため

<br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br>

**実施記録**

```java
}
```
