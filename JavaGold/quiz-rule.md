Java Gold 出題ワークフロー

Silverの chapter2 運用(java-study/quiz-rule.md)をGold用に移植したもの。記録先は別セッションへの中継ではなく、このリポジトリ配下の Markdown ファイルに直接書き込む。

① ソース確認
sample/chapN/M/Main.java(またはexM)を読む。まだ手を付けていない番号から順に進める(ユーザーが番号を指定すればそれを優先)。

② 動作検証(javac/java)
scratchpadに.javaファイルを書いて実際にjavac＋javaで実行し、出力・コンパイルエラーの有無を確認する。記憶や仕様の推測だけで断定しない。

③ 問題提示(チャット上)
- 問題文＋コード(行番号付き)＋選択肢(A〜D、基本は1つ選択、複数選択もあり)
- 選択肢に「〜と誤解」のような注釈は付けない(答えが透けるため)
- コンパイルエラーを選ばせる形式のとき、選択肢に理由を書き込まない(理由は解説側)
- チャット上では<br>スペーサーを付けない
- デフォルトで難問(複合的な引っかけ)を出す
- 複数ファイルにまたがる問題はコードブロックごとにファイル名/パッケージを明記する
- 正解の文字(A〜D)が連続して偏らないようにする
- 出題後は一旦止めてユーザーの回答を待つ(勝手に次に進まない)

④ 採点・解説
回答を待ってから正誤判定。正解でも不正解でも解説(概念)を書く。間違っていれば「何が引っかかりポイントだったか」を言語化する。ユーザーからの概念的な質問はその場で回答し、疑問として記録する。

⑤ 記録
chapterN_practice/problems_v1.md に追記する。番号はソースファイル単位: sample/chapN/M由来なら問題M-K(例: 問題1-1)、exM由来なら問題exM-K。
見出しの直前に `<a id="問題M-K"></a>` を置き、目次はそのidにリンクする(自動スラッグはプレビュー実装依存でズレることがあるため)。
書式:
```
<a id="問題M-K"></a>
## 問題M-K
問題文 / コード / 選択肢
**実施記録**




迷ったポイント: ...




解説(概念): ...




正解: ...




あなたの回答: ...
```
順序は 迷ったポイント → 解説(概念) → 正解 → あなたの回答。各項目の間は空行5行分あける。「正解」と「あなたの回答」を下に離しておくのは、解き直したときに先に答えが目に入って先入観になるのを避けるため。
疑問があれば **疑問**: 質問 -> 回答 を追記

⑥ 次に進む条件
ユーザーが明示的に次を指示するまで先に進まない。
