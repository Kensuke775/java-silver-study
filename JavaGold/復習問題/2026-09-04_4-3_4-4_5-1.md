## 復習1(4.3 Queue/Deque)

```java
1  import java.util.ArrayDeque;
2  import java.util.Deque;
3  import java.util.Iterator;
4
5  public class Main {
6      public static void main(String[] args) {
7          Deque<Integer> deque = new ArrayDeque<>();
8          deque.add(1);
9          deque.add(2);
10         deque.add(3);
11         Iterator<Integer> it = deque.descendingIterator();
12         while (it.hasNext()) {
13             System.out.print(it.next() + " ");
14         }
15     }
16 }
```

このコードを実行するとどうなるか。

A. `1 2 3 ` が出力される

B. `3 2 1 ` が出力される

C. コンパイルエラーになる(`descendingIterator()`というメソッドは存在しない)

D. 実行時に例外がスローされる

**実施記録**




迷ったポイント: なし(一発正解)。




解説(概念): `descendingIterator()`は`Deque`専用のメソッドで、末尾側から先頭側へ向かって辿る`Iterator`を返す。`[1,2,3]`(先頭から1,2,3の順)を逆方向に辿るので`3 2 1`の順で出力される。`it.next()`は元のコレクションから要素を削除するわけではなく、Iterator内部のカーソル位置を進めながら値を返すだけ。




正解: B




あなたの回答: B

## 復習2(4.3 Queue: PriorityQueue)

```java
1  import java.util.PriorityQueue;
2  import java.util.Queue;
3
4  public class Main {
5      public static void main(String[] args) {
6          Queue<Integer> pq = new PriorityQueue<>();
7          pq.add(30);
8          pq.add(10);
9          pq.add(20);
10         System.out.println(pq.peek());
11         System.out.println(pq.poll());
12         System.out.println(pq.poll());
13         System.out.println(pq);
14     }
15 }
```

このコードを実行するとどうなるか。

A. `30` → `30` → `10` → `[20]`

B. `10` → `10` → `20` → `[30]`

C. `10` → `30` → `10` → `[20]`

D. `30` → `10` → `20` → `[30]`

**実施記録**




迷ったポイント: `PriorityQueue`が「追加した順」や「先頭に入れたものから」取り出されると誤認していた。実際は常に自然順序(小さい順)で並べ替えて保持しており、`peek()`/`poll()`は常に「現時点で一番小さい要素」を返す。




解説(概念): `PriorityQueue`は追加順に関係なく、常に最小値が先頭に来るように内部で管理される。`peek()`で最小の`10`、`poll()`で`10`→`20`の順に取り出され、残りは`[30]`になる。




正解: B




あなたの回答: A

追記: `PriorityQueue`はデフォルトでは自然順序(昇順、最小値が先頭)だが、コンストラクタに`Comparator`を渡すと順序を反転できる。

```java
Queue<Integer> pq = new PriorityQueue<>(Comparator.reverseOrder());
pq.add(30);
pq.add(10);
pq.add(20);
System.out.println(pq.peek()); // 30
System.out.println(pq.poll()); // 30
System.out.println(pq.poll()); // 20
System.out.println(pq);        // [10]
```

`Comparator.reverseOrder()`を渡すことで「大きい値ほど優先度が高い」扱いになり、`peek()`/`poll()`が最大値から返ってくるようになる(最大値優先キュー、いわゆるmax-heap的な使い方)。中身のデータ構造自体(二分ヒープ)は変わらず、比較のルールが逆転するだけ。

## 復習3(4.4 Map: merge)

```java
1  import java.util.HashMap;
2  import java.util.Map;
3
4  public class Main {
5      public static void main(String[] args) {
6          Map<String, Integer> map = new HashMap<>();
7          map.put("a", 5);
8          map.merge("a", 10, (oldV, newV) -> oldV + newV);
9          map.merge("b", 100, (oldV, newV) -> oldV + newV);
10         System.out.println(map);
11     }
12 }
```

このコードを実行するとどうなるか。

A. `{a=15, b=100}`

B. `{a=10, b=100}`

C. `{a=15, b=110}`

D. 9行目で`NullPointerException`がスローされる(既存の値がないためラムダ内で`oldV`がnullになる)

**実施記録**




迷ったポイント: `merge()`が初見のメソッドで、キーが存在しない場合の挙動を誤解していた(`oldV`にnullが渡って関数が呼ばれると誤認)。実際はキーが存在しない場合、関数は一切呼ばれず、渡した値がそのまま登録される。




解説(概念): `merge(key, value, 関数)`は、キーが既に存在する場合のみ関数`(oldV, newV) -> ...`を実行しその結果で上書きする。キーが存在しない場合は関数を呼ばずに`value`をそのまま新規登録する。`"a"`は既存値`5`に`10`を足して`15`、`"b"`は新規登録で`100`がそのまま入り、結果は`{a=15, b=100}`。




正解: A




あなたの回答: C

## 復習4(4.4 Map: getOrDefault/computeIfAbsent)

```java
1  import java.util.HashMap;
2  import java.util.Map;
3
4  public class Main {
5      public static void main(String[] args) {
6          Map<String, Integer> map = new HashMap<>();
7          map.put("a", 1);
8          int v1 = map.getOrDefault("a", 0);
9          int v2 = map.getOrDefault("b", 99);
10         System.out.println(v1 + " " + v2);
11         System.out.println(map.containsKey("b"));
12         map.computeIfAbsent("c", k -> 500);
13         System.out.println(map);
14     }
15 }
```

このコードを実行するとどうなるか。

A. `1 99` → `false` → `{a=1, c=500}`

B. `1 99` → `true` → `{a=1, b=99, c=500}`

C. `1 0` → `false` → `{a=1, c=500}`

D. `1 99` → `false` → `{a=1}`

**実施記録**




迷ったポイント: `getOrDefault("b", 99)`が指定したデフォルト値(`99`)ではなく`0`を返すと誤認していた。`getOrDefault`は「値を返すだけでmapの中身は変えない」、`computeIfAbsent`は「値を返しつつ実際にmapへ登録する」という違いがある。




解説(概念): `getOrDefault("a", 0)`はキーが存在するので登録値`1`を返す。`getOrDefault("b", 99)`はキーが存在しないので指定したデフォルト`99`をそのまま返す(mapに`"b"`は追加されないので`containsKey("b")`は`false`)。`computeIfAbsent("c", k -> 500)`はキーが存在しないので関数を実行し`500`を実際に登録する。結果は`"1 99"`→`false`→`{a=1, c=500}`。




正解: A




あなたの回答: C

## 復習5(5.1 Comparable: Collections.sortとの違い)

```java
1  import java.util.ArrayList;
2  import java.util.Collections;
3  import java.util.List;
4
5  record Item(String name) {}
6
7  public class Main {
8      public static void main(String[] args) {
9          List<Item> list = new ArrayList<>();
10         list.add(new Item("Banana"));
11         list.add(new Item("Apple"));
12         Collections.sort(list);
13         System.out.println(list);
14     }
15 }
```

このコードを実行するとどうなるか。

A. コンパイルエラーになる

B. 12行目で実行時に`ClassCastException`がスローされる

C. `[Item[name=Apple], Item[name=Banana]]`が出力される

D. `[Item[name=Banana], Item[name=Apple]]`(追加順のまま)が出力される

**実施記録**




迷ったポイント: `TreeSet`のとき(実行時に`ClassCastException`)と同じ挙動になると誤認していた。実際は`Collections.sort(List<T> list)`のシグネチャ自体が`T extends Comparable<? super T>`という型パラメータの境界を持っており、`Item`がComparableを実装していないとコンパイルの時点で弾かれる。`TreeSet.add(E e)`にはこの境界がなく実行時に初めて失敗する、という違いがある。




解説(概念): 同じ「Comparableを実装していない」という原因でも、失敗するタイミングが道具によって変わる。`Collections.sort()`は呼び出す前からコンパイラが型パラメータの境界をチェックできるためコンパイルエラー、`TreeSet`は境界がなく実行時に`compareTo()`を呼んで初めて失敗する、という対比がこの問題のポイント。




正解: A




あなたの回答: B

## 復習6(5.1 Comparable: Collections.max/sort)

```java
1  import java.util.ArrayList;
2  import java.util.Collections;
3  import java.util.List;
4
5  record Product(String name, int price) implements Comparable<Product> {
6      @Override
7      public int compareTo(Product o) {
8          return this.price - o.price;
9      }
10 }
11
12 public class Main {
13     public static void main(String[] args) {
14         List<Product> list = new ArrayList<>();
15         list.add(new Product("Pen", 100));
16         list.add(new Product("Notebook", 300));
17         list.add(new Product("Eraser", 50));
18         System.out.println(Collections.max(list));
19         Collections.sort(list);
20         System.out.println(list);
21     }
22 }
```

このコードを実行するとどうなるか。

A. `Product[name=Notebook, price=300]` → `[Product[name=Eraser, price=50], Product[name=Pen, price=100], Product[name=Notebook, price=300]]`

B. `Product[name=Pen, price=100]` → `[Product[name=Pen, price=100], Product[name=Notebook, price=300], Product[name=Eraser, price=50]]`

C. `Product[name=Notebook, price=300]` → `[Product[name=Notebook, price=300], Product[name=Pen, price=100], Product[name=Eraser, price=50]]`

D. 18行目でコンパイルエラーになる

**実施記録**




迷ったポイント: なし(一発正解)。




解説(概念): `Collections.max()`は`compareTo()`を使って最大の要素を探す。`price`基準の`compareTo()`なので`price`が一番高い`Notebook(300)`が返る。`Collections.sort()`は`price`の昇順に並べ替えるので`[Eraser(50), Pen(100), Notebook(300)]`になる。




正解: A




あなたの回答: A
