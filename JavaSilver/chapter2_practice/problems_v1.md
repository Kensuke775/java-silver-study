## 問題1

**要点**

- アンダースコア(`_`)は数値リテラルの可読性を上げるための区切り文字。**値自体には一切影響しない**（コンパイル時に単純に無視される）
- アンダースコアが使えない位置：①数値の先頭・末尾、②小数点の直前・直後、③`F`/`D`/`L`などサフィックスの直前、④`0x`（16進数）・`0b`（2進数）プレフィックスの途中・直後
- 上記以外（数字と数字の間）はいくつ連続しても○（`1___0`のようにアンダースコアが連続してもOK）
- **例外**：8進数の先頭`0`は`0x`/`0b`のような特別なプレフィックス扱いされない、ただの数字の1つ。そのため先頭`0`の直後にアンダースコアを置いてもエラーにならない（`0_777`はOK）

次のコードのうち、コンパイルエラーになる行はどれですか。（3つ選択）

```java
public class Main {
    public static void main(String[] args) {
        int a = 3_600;
        int b = 900_;
        int c = 0x_1F;
        double d = 9.8_1;
        int e = 0_777;
        float f = 2.5_F;
    }
}
```

A. `int a = 3_600;`
B. `int b = 900_;`
C. `int c = 0x_1F;`
D. `double d = 9.8_1;`
E. `int e = 0_777;`
F. `float f = 2.5_F;`

<br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br>

**実施記録**

回答：B, C, F
正解：B, C, F
迷ったポイント：なし

## 問題2

**要点（発展編）**

- 前問の4パターン＋8進数例外に加え、以下の2点も押さえておく
- **`_56`のような「先頭アンダースコア」は、実は数値リテラルの構文エラーではない。** アンダースコアは識別子（変数名）としても使える文字なので、Javaのレキサ（字句解析）は`_56`をまるごと「1つの識別子」として読む。結果、`int b = _56;`は「`_56`という名前の変数が見つからない」というシンボル解決エラー（`シンボルを見つけられません`）になる。**「先頭アンダースコアの数値リテラルは不正」という理由でコンパイルエラーになっているわけではない**（結果的にどちらもコンパイルは通らないが、エラーの原因は別物）
- 指数表記（`e`/`E`）でも同じ4分類のルールが適用される：`e`の**直前・直後**にアンダースコアは置けないが、指数部の**数字と数字の間**（例：`12e1_0`）は通常の数字列と同じで問題ない

次のコードの各行に関する説明のうち、**誤っているもの**はどれですか。（3つ選択）

```java
public class Main {
    public static void main(String[] args) {
        int a = 4_2_0;
        int b = _56;
        long c = 78_;
        double d = 5_.5;
        double e = 5._5;
        long f = 100_L;
        int g = 0b_110;
        int h = 0_x1A;
        int i = 0_53;
        double j = 12e1_0;
    }
}
```

A. `int a = 4_2_0;` は、数字と数字の間であればアンダースコアを連続して複数個置いても問題なくコンパイルできる
B. `int b = _56;` は、数値リテラルの先頭にアンダースコアを置くルール違反として、コンパイルエラーになる
C. `long c = 78_;` は、末尾にアンダースコアがあるため、「不正なアンダースコアです」というコンパイルエラーになる
D. `double d = 5_.5;` は、小数点の直前にアンダースコアがあるため、コンパイルエラーになる
E. `double e = 5._5;` は、小数点の直後であっても、数字と数字の間と同様にアンダースコアが許可されるため、問題なくコンパイルできる
F. `long f = 100_L;` は、サフィックス`L`の直前にアンダースコアを置くことができないために生じるコンパイルエラーである
G. `int g = 0b_110;` は、2進数プレフィックス`0b`の直後にアンダースコアを置いているため、コンパイルエラーになる
H. `int h = 0_x1A;` は、`0x`というプレフィックスの途中にアンダースコアを割り込ませた書き方であり、これも「不正なアンダースコアです」というコンパイルエラーになる
I. `int i = 0_53;` は、先頭の`0`が`0x`や`0b`と同じ「特別なプレフィックス」として扱われるため、直後にアンダースコアを置くとコンパイルエラーになる
J. `double j = 12e1_0;` は、アンダースコアが指数部の数字と数字の間に置かれているだけであり、`e`の直前・直後ではないため、コンパイルエラーにはならない

<br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br>

**実施記録**

回答：E, I, J
正解：B, E, I
迷ったポイント：Bを見落とし、代わりにJを誤って選択。Jは指数部の数字間のアンダースコアで正しい説明（eの直前直後ではないのでOK）。Bは「先頭アンダースコアの数値リテラルは不正」という理由づけ自体が誤りで、実際は`_56`が識別子として読まれてのシンボル解決エラーという点を見抜けなかった。

## 問題3

**要点**

- アンダースコアは値そのものには一切影響しない。数字と数字の間にあるアンダースコアは、コンパイル時に単純に無視されるだけ
- `println`などで出力されるとき、`int`/`double`はどの進数（2進数・8進数・16進数）で書かれたリテラルであっても、**常に10進数の値に変換されてから**出力される（書いた見た目の桁がそのまま表示されるわけではない）
- 8進数の先頭`0`は特別なプレフィックスではないので、アンダースコアの合否判定にも出力結果にも影響しない（`0_172`は8進数の172＝10進数の122）
- **位取り計算の具体例**：アンダースコアを除去した上で、右端の桁を`(その進数)⁰`、その左を`(その進数)¹`……として、各桁の数字にその重みを掛けて全部足す

  ```
  a = 0b1_010_011（2進数）→ 83
  桁:  2⁶ 2⁵ 2⁴ 2³ 2² 2¹ 2⁰
  値:   1  0  1  0  0  1  1
      = 64 + 0 + 16 + 0 + 0 + 2 + 1 = 83

  b = 0_172（8進数）→ 122　※先頭の0は「8進数」の目印であり、値の計算には使わない
  桁:  8²  8¹  8⁰
  値:   1   7   2
      = 1×64 + 7×8 + 2×1 = 64 + 56 + 2 = 122

  c = 0x2_C（16進数）→ 44　※A〜Fは10〜15に対応（C = 12）
  桁: 16¹ 16⁰
  値:  2   C(=12)
     = 2×16 + 12×1 = 32 + 12 = 44
  ```

次のコードの実行結果として正しいものを1つ選んでください。

```java
public class Main {
    public static void main(String[] args) {
        int a = 0b1_010_011;
        int b = 0_172;
        int c = 0x2_C;
        double d = 4_2.0_5;
        System.out.println(a + ", " + b + ", " + c + ", " + d);
    }
}
```

A. `83, 122, 44, 42.05`
B. `1010011, 172, 2C, 42.05`
C. `83, 172, 44, 42.05`
D. コンパイルエラーが発生する

<br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br>

**実施記録**

回答：A
正解：A
迷ったポイント：なし（正解後、2進数・8進数の位取り計算のやり方について確認質問あり——参考「進数変換の計算方法」に追記）

## 問題7

**要点（3桁以上の多桁変換、要注意）**

- 桁が増えても考え方は同じ：**右端の桁が常にその進数の0乗（＝1）**、そこから左に1桁進むごとに指数が1つずつ増えていく
- 3桁の16進数`XYZ`なら、`X×16² + Y×16¹ + Z×16⁰`。**Xの指数は「桁数-1」**（3桁なら2乗、4桁なら3乗）になる。「全部の桁に同じ16¹を掛ける」という計算は誤り
- 8進数・2進数でも同じ：それぞれ`8²/8¹/8⁰`、`2⁷/2⁶/…/2⁰`のように、桁ごとに指数が1つずつ増える

次のコードの実行結果として正しいものを1つ選んでください。

```java
public class Main {
    public static void main(String[] args) {
        int a = 0x1_B3;
        int b = 0b1101_0010;
        int c = 0_572;
        System.out.println(a + ", " + b + ", " + c + ", " + (a + c));
    }
}
```

A. `435, 210, 378, 813`
B. `195, 210, 98, 293`
C. `435, 210, 378, 803`
D. コンパイルエラーが発生する

<br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br><br>

**実施記録**

回答：D
正解：A
迷ったポイント：`b`の2進数変換（2⁷+2⁶+2⁴+2¹=210）は自力で正しく計算できていたが、最終的にDと誤答。個々の値の計算が合っていても「コンパイルエラーだろう」と反射的に結論づけてしまう傾向があり、4つのNGパターン（先頭・末尾／小数点前後／サフィックス直前／0x・0bプレフィックスの途中・直後）のどれにも該当しないことを確認する一手間を忘れがち。

## 問題19

**要点**

- ローカル変数の確定的代入（definite assignment）は、**すべての実行経路**で代入が行われるかどうかをコンパイラが機械的に判定するルール。`if`/`else`の両方の分岐で代入していれば、どちらの経路をたどっても初期化済みと判断される。
- `if`だけで`else`がない場合、その分岐を通らない経路が存在するため、通常はコンパイラは初期化を保証できずコンパイルエラーになる。
- ただし、条件式が`final`かつコンパイル時定数（例：`final boolean flag = true;`）である場合、コンパイラは到達不能コードの判定に条件式の値を利用でき、この場合`else`が存在しなくても初期化済みと判断できることがある。`final`であっても初期化式が非`final`変数を含むなど定数式でない場合（例：`final boolean cond = (p > 0);`）は、この特例は適用されない。
- 変数の初期化式の右辺で、その変数自身をまだ何の値も持たない状態で参照するとコンパイルエラーになる。
- static変数（フィールド）はローカル変数と異なり、明示的な初期化をしなくても型ごとのデフォルト値が自動的に入るため、未初期化のまま読み取ってもコンパイルエラーにはならない。

次の6つの独立したコード（それぞれ別々のプログラムの中身）について、下のA〜Fの説明のうち**誤っているもの**はどれですか。（2つ選択）

```java
// a
int x, y;
x = 1;
System.out.println(x);
```

```java
// b
int x;
boolean flag = true;
if (flag) {
    x = 1;
} else {
    x = 2;
}
System.out.println(x);
```

```java
// c
int x;
boolean flag = true;
if (flag) {
    x = 1;
}
System.out.println(x);
```

```java
// d
int x;
final boolean flag = true;
if (flag) {
    x = 1;
}
System.out.println(x);
```

```java
// e
int x = x + 1;
System.out.println(x);
```

```java
// f
class Holder {
    static int x;
}
System.out.println(Holder.x);
```

A. aはコンパイルが通る。`y`は宣言されているだけで読み取られていないため、初期化の有無は問題にならない。

B. bはコンパイルが通る。`if`と`else`の両方の分岐で`x`に代入しているため、コンパイラはどちらの経路でも`x`が初期化されると判断できる。

C. cはコンパイルエラーになる。`x`への代入が`if`ブロックの中にしかなく、`else`側が存在しないため、コンパイラは全経路での初期化を保証できない。

## 問題5-2

**要点**

- ローカル変数の確定的代入と同じく、`int`から`long`への変換、`int`から`float`・`double`への変換は拡大変換（widening）にあたり、常に暗黙的に許可される。`int`から`float`への拡大変換は非常に桁数の大きい値では精度が落ちることがあるが、それでも仕様上は拡大変換として無条件に許可される。
- 一方、`double`から`float`への変換は縮小変換（narrowing）にあたり、値の大小に関わらず常に明示的な変換（`F`サフィックスやキャスト）が必要になる。
- 整数リテラルを`byte`型の変数に代入する際の「範囲内なら暗黙変換OK」という特例は、代入元が**真のコンパイル時定数**である場合にのみ適用される。代入元が`final`の付いていない普通の変数であれば、たとえ実行時の値が範囲内であっても、この特例は適用されない（`final`かつ非定数式なら定数式とみなされないのと同じ理屈）。

```java
System.out.println(f);
```

```java
System.out.println(b);
```

```java
// e

byte b = n;
System.out.println(b);
```

```java
// f
double d = 5;
System.out.println(d);
```

A. aはコンパイルが通る。`1000`はint範囲に収まっており、int→longは拡大変換なので、`L`サフィックスがなくても常に暗黙的に許可される。

B. bはコンパイルエラーになる。小数点付きリテラル`1.5`は値の大きさに関わらずdouble型として解釈され、double→floatは縮小変換にあたるため、暗黙変換は許可されない。

- 一方、`var str = "World";`は初期化子`"World"`から型が推論されるため、`str`の静的な型は`String`になる。そのため`str`を引数に渡すと`show(String)`が呼ばれる。
- つまり`var`は「型が曖昧になる」わけではなく、初期化子から確定した具体的な型を持つ、通常の型宣言と同等の変数になる。
- **オーバーロード解決（どのメソッド定義を呼ぶか）は、コンパイル時に引数の静的型（変数の宣言型／`var`の推論結果）だけを見て決まる。** コンパイラがこの判断をコンパイル時点で終わらせてバイトコードに焼き付けるため、実行時に変数が実際にどのオブジェクトを指しているか（動的型）は一切関係しない。
- これは**メソッドのオーバーライド（動的ディスパッチ）とは対照的**な仕組み。オーバーライドは実行時に動的型（実際のオブジェクトの実クラス）を見て、どのサブクラスの実装を呼ぶかを決める。一方オーバーロードの選択は静的ディスパッチで、実行時の型は無関係に、コンパイル時の静的型だけで決まる。

## 参考：進数変換の計算方法

問題3の`a`（2進数）・`b`（8進数）に関連して、実際に計算方法を確認した内容。`c`（16進数）も同じ考え方。

**共通の手順**：アンダースコアを除去した上で、右端の桁を`(その進数)⁰`、その左を`(その進数)¹`……として、各桁の数字にその重みを掛けて全部足す。

**a = `0b1_010_011`（2進数）→ 83**

```
桁:  2⁶ 2⁵ 2⁴ 2³ 2² 2¹ 2⁰
値:   1  0  1  0  0  1  1
    = 64 + 0 + 16 + 0 + 0 + 2 + 1 = 83
```

**b = `0_172`（8進数）→ 122**

先頭の`0`は「これは8進数」という目印（プレフィックス）であり、値の計算には使わない。アンダースコアを除去した残りの`172`だけを8進数として計算する。

```
桁:  8²  8¹  8⁰
値:   1   7   2
    = 1×64 + 7×8 + 2×1 = 64 + 56 + 2 = 122
```

**c = `0x2_C`（16進数）→ 44**

16進数の`A〜F`は`10〜15`に対応する（`C = 12`）。

```
桁: 16¹ 16⁰
値:  2   C(=12)
   = 2×16 + 12×1 = 32 + 12 = 44
```
