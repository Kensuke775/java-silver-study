## 1. `final`変数がwhile/forの条件式に絡むと、値が畳み込まれてコンパイルエラーになることがある——見極めは「finalかどうか」ではなく「finalかつ初期値がコンパイル時定数式かどうか」

問題11-5、ex8-3・ex8-4（2周目オリジナル）より。

```java
final int a = 1, b = 2;
while (a + 1 == b) {      // a+1==b は 1+1==2 → true に畳み込まれる
    System.out.print("*");
}
System.out.print("end");  // ← このend行がコンパイルエラー(到達不能コード)になる
```

```java
int x = 1, y = 2;         // final を外しただけ
while (x + 1 == y) {      // 値を静的に追跡しないので畳み込まれない
    System.out.print("*");
}
System.out.print("end");  // ← コンパイルは通る(実行すると本当に無限ループになる)
```

判定基準は**「finalかどうか」ではなく「finalであり、かつ初期値がリテラル・他の定数変数・それらの演算/比較/キャスト/三項演算子だけで組み立てられているか」**(JLS 4.12.4の「定数変数」)。この2条件がそろって初めて、コンパイラは値をコード上に直接書いたのと同じように畳み込む。

**チェックリスト**

1. `final`が付いているか？ → 付いていなければこの話は無関係。値がどうであれ静的に追いかけないので、while/forの条件がどんな式でも普通にコンパイルは通る(実行時に無限ループになるかは別問題)。
2. `final`なら、初期値はリテラル・他の定数変数・それらの演算/比較/論理演算/キャスト/三項演算子**だけ**で組み立てられているか？ → Yesなら定数変数として畳み込まれる。
3. 途中にメソッド呼び出し(`getZero()`など)・配列アクセス・非final変数の参照・`new`・インスタンスフィールドアクセスが1つでも混ざっていないか？ → 混ざっていれば、たとえ`final`が付いていても定数式にはならず、畳み込みは起きない(単に「一度しか代入できない変数」というだけになる)。

**このルールが効くのはwhile/forの条件式だけ**で、`if`文は気にしなくてよい。`if`の本体は「条件の値に関わらず常に到達可能」という特例がJLSに明記されているため、finalかどうか・定数式かどうかに関わらず常にコンパイルが通る。一方while/forにはその特例がなく、条件が定数式として静的に`false`と確定すれば本体が、`true`と確定すれば(`break`が一つもない場合)後続の文が到達不能コードとしてエラーになる。
