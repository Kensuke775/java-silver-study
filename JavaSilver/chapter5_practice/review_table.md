一周目メモ  

1-1の疑問

- **デフォルトコンストラクタが作られるか**: `Item`にはコンストラクタが1つも書かれていないので、コンパイラが自動的に「引数なし・中身が空」のコンストラクタを生成します。書くとすれば`public Item() { }`と同じもの(正確には内部的に`super();`だけが入る)です。
- **中身は何か**: 文字通り**何もしていません**。フィールドへの代入も何もない、空っぽのコンストラクタです。

7-2の疑問  
public class Sample {     public void printItem(String[] s, int i) {}     public boolean printItem(int i, String[] s) { return true; } } この問題ってさ、これって合法なんですか？順序が逆なだけ。  

はい、合法です。オーバーロードの判定は「引数の型の並び順」で行われるので、`(String[], int)`と`(int, String[])`は型の順序が違う別のシグネチャとして扱われ、問題なく共存できます。

オーバーロードは「メソッド名+引数の型と順序」の組み合わせで区別されるため、型の集合が同じでも並び順が異なれば別メソッドとして成立します。

9-1の疑問  

1つのメソッドに可変長引数を2つ書くことは、そもそも構文として不可能です。可変長引数(`...`)は「最後のパラメータでなければならない」というルールがあるため、1つ目の可変長引数を書いた時点でそれが最後でなければエラーになります。

```java
public void method(int... a, String... b) {}

```

```
エラー: 可変引数パラメータは最後のパラメータにする必要があります

```

つまり「メソッド単体に可変長引数が2つ」というケースは常にコンパイルエラーで、位置が先頭だろうが末尾だろうが関係なく成立しません。可変長引数は1メソークにつき最大1個までです。

一方、「クラス内に可変長引数を使うメソッドが複数存在する」(9-1のSampleのように)のは全く別の話で、こちらは問題なく共存できます。

11-1の復習

コンストラクターが対応するものがない場合、コンパイルエラーを疑わなければいけない。  
デフォルトコンストラクターはコンストラクターがないときに自動生成されるものであって、コンストラクターがあるときは自動生成されずにコンストラクターを作ってくださいっていうコンパイルエラーが発生する。

```java
public class Item {
    private int id;
    private String name;
    public Item(int id, String name) {
        this.id = id;
        this.name = name;
    }
    public void printItem() {
        System.out.println("Item id:" + id + " name:" + name);
    }
    public static void main(String[] args) {
        Item item = new Item();
        item.printItem();
    }
}
```



## 問題13-1

`commonValue`は`int`型(プリミティブ型)なので、`==`は値そのものを比較します。参照比較になるのはオブジェクト型(Stringなど)の場合だけで、プリミティブ型の`==`は常に値比較です。

さらに言うと、`commonValue`は`static`なので、`s1.commonValue`と`s2.commonValue`はそもそも「別々のインスタンスが持つ別々の値」を比較しているのではなく、クラスに1つしかない同じ変数を2回読んでいるだけです。`s1.commonValue = 999;`でその唯一の変数が999に書き換わっているので、`s1.commonValue`も`s2.commonValue`も同じ999を指しており、当然`true`になります。

またイントはプリミティブ型だから、値そのものを比較する。  ここも型が関係してきてるんですね。  なるほど。

そうです。`==`の挙動は「変数の型」で決まります。

- プリミティブ型(int, boolean, charなど) → 値そのものを比較
- 参照型(String, 自作クラスなど) → 参照先(メモリ上の同一オブジェクトか)を比較

同じ`==`という演算子でも、左右の変数の型によって「何を比較しているか」が根本的に変わる、というのがポイントです。

```java
public class Sample {
    int value = 100;
    static int commonValue = 500;
    public void printValue() {
        System.out.println("instance value : " + value);
    }
    public static void printCommonValue() {
        System.out.println("static common value : " + commonValue);
    }
}
public class Main {
    public static void main(String[] args) {
        Sample s1 = new Sample();
        Sample s2 = new Sample();
        s1.commonValue = 999;
        s2.printCommonValue();
        Sample.printCommonValue();
        System.out.println(s1.commonValue == s2.commonValue);
    }
}
```



## 問題12-1の疑問

もしコンストラクターがなかった場合、コンパイルエラーになります。

`this(0, "T-shirt")`が呼び出そうとしている「`int, String`を受け取るコンストラクタ」がこのクラスに存在しないことです。

```
エラー: クラス Itemのコンストラクタ Itemは指定された型に適用できません。
        this(0, "T-shirt");
  期待値: 引数がありません
  検出値:    int,String
  理由: 実引数リストと仮引数リストの長さが異なります

```

まさに最初のあなたの理解通り、「`this()`で呼び出す型に合ったコンストラクタがないとコンパイルエラーになる」という点がそのまま実証された形です。

```java
public class Item {
    private int id;
    private String name;
    public Item() {
        System.out.println("before this()");
        this(0, "T-shirt");
    }
    public void printItem() {
        System.out.println("Item id:" + id + " name:" + name );
    }
    public static void main(String[] args) {
        new Item().printItem();
    }
}
```
